# Практическая реализация в облаке

Пакет — контент и спецификация, не приложение. Создай исходники в рабочем репозитории, сохрани материалы. Проверь имеющийся код до инициализации проекта. Рекомендуемый стек: React + TypeScript + Vite; маршрутизация по URL; GSAP для анимаций. Установи совместимые зависимости и сохрани lockfile; номера версий здесь намеренно не зафиксированы.

## Структура

Удобное разбиение: GalleryScene, GalleryItem, ProjectIndex, ProjectMeta, CornerFrame, SiteHeader, ProjectPage, ProjectMedia и контроллер переходов. Контент импортируется из единого манифеста. Не дублируй вручную 16 разных страниц с расходящимися URL.

`projects/` содержит исходные материалы. Подготовь каталог public/media или импортируемые ассеты, переписав пути контролируемым скриптом. Обложки используй через `gallery_cover`, полный набор кейса — через `screenshots`. Не оставляй абсолютные пути и файловые ссылки на компьютер владельца.

Изображения: создай подходящие WebP/AVIF варианты обложек с сохранением исходников, ширины примерно 480/960/1600 px без бессмысленного увеличения исходного разрешения. Запиши размеры, используй srcset/sizes, preload только первого нужного кадра. Ближайшие соседи загружаются заранее, остальные отложенно. Не загружай все длинные full-page изображения на главной. Для логотипа подготовь обрезанный по alpha PNG; файл на белом оставь как превью.

## Архитектура движения

Выбери один источник scroll position. Если используется собственный инерционный контроллер галереи, Lenis на главной не нужен. Если Lenis — не добавляй второй независимый lerp поверх его scroll. GSAP отвечает за переходы и transforms, React — за структуру и данные. Не делай setState на каждом кадре всего дерева.

Используй transform и opacity; фильтр на умеренном количестве видимых изображений. Виртуализируй дальние кадры, очищай RAF/слушатели при переходе. При reduced-motion не запускай бесконечный декоративный RAF без необходимости. Без WebGL сайт обязан оставаться работоспособным: обычный DOM достаточен для этого задания.

Маршруты `/projects/:slug` должны переживать refresh. Добавь конфигурацию SPA fallback для выбранного хостинга и объясни её; не разворачивай приложение без отдельного поручения. Включи осмысленную 404 для неизвестного slug. У каждой страницы title, description и canonical с настраиваемым базовым доменом; пока домен не определён, не выдумывай production-адрес. Preview должен быть закрыт от индексации до настройки домена.

Контакт — обычная работающая ссылка на Telegram. Никаких секретов, API-ключей, фиктивной формы отправки и необходимости backend. Кейс с ORBIT показывает статус «Демо».

## Проверка результата

Сначала доведи геометрию главной с реальными изображениями; затем движение; затем маршруты и кейсы; затем mobile; затем пройди ACCEPTANCE.md. Визуальная проверка обязательна. Скриншоты макета внутри браузера не являются реализацией.

В QA.md укажи выполненные команды и исходы, окружение браузера, размеры, сделанные снимки и запись движения, проверенные маршруты, расхождения и ограничения. Если запуска или браузера нет, не заявляй успешную сборку или pixel-perfect. Сохрани инструкции запуска и production build в README приложения.
